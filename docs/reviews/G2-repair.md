# wxread 功能与页面修复复核

依据为用户要求、原始 PLAN / DESIGN 和 G0 需求清单，代码基线为 GitHub 上的 b9654d1。

## 并发状态写入

旧实现发生冲突后重新读取 sha，却继续提交旧的整份内容。新回归分别复现了计划覆盖通知、账户备注覆盖新 Cookie、并发记录丢失，以及同一运行重复入库，旧实现四项全部失败。

状态变更现在从同一次读取的密文和 sha 开始。冲突后重新解密最新数据并重新应用本次变更。管理指令只修改对应字段，运行记录以 run_id 防止重复追加。保留原有加密格式和旧数据读取能力。

已验证 29 个状态及管理测试。测试使用内存 Contents 后端与故障注入，这些结果验证并发变更逻辑，真实 GitHub 写入留待获得运行权限后验证。

## 扫码参数与凭据

扫码捕获保留 JSON 数值和零值，旧记录里的 ci/co/pr 数字字符串在读取时兼容转换。抓取阅读参数后重新读取浏览器 Cookie，再合并到当前账户，保护同期的备注和目标设置。参数尚未补全的账户也能修改备注和停用。

三项新回归在修复前全部失败。浏览器页面替身验证参数类型、抓取后凭据轮换和不完整账户编辑。微信真实扫码与阅读参数有效性仍需真机验收。

## 指令排队与回执

Actions 通过自身 run_id 读取 GitHub 的 created_at，以接收运行的时刻校验原有60秒窗口。排队和安装浏览器后的等待不再使新指令过期，已过期和重复会话仍被拒绝。验证拒绝也写加密失败回执，重放不会覆盖原回执。扫码确认登录时先写 pending/capturing 阶段回执，再获取阅读参数并写最终结果。

两个新增 worker 回归在修复前失败，覆盖三分钟排队和过期失败回执。真实 GitHub 运行时间查询需要 control 工作流的 actions: read 权限，已写入工作流。

## 阅读传输与恢复

HTTP错误及非法JSON响应仍回报Set-Cookie，Reader先合并凭据再处理错误。纯网络故障保持账户可重试，明确会话失效才进入重绑状态。每个未完成读取的恢复次数按故障类型记录，交替故障不能刷新恢复预算。参数失效按原方案先修章节再续期，第一次正常读取也等待对应的阅读间隔。运行记录带唯一run_id。

四个新回归在修复前失败，另补非法JSON保留Cookie的回归。已有两个测试原先把网络失败当成登录失效，或把成功响应当作续期失败，已按实际错误脚本调整。验证采用传输替身，微信服务端实际计时留待真跑。

## 作业中断与账户隔离

JobRunner通过finally写最终结果，异常账户不会终止后续账户。凭据变化即时回写，阅读进度每10次回写一次，默认间隔下约5分钟。运行时仅合并凭据、健康状态与progress字段，保护页面修改的备注、目标和启用开关。删除的账户不会复活，重新绑定后旧运行停止并保留新凭据。SIGINT/SIGTERM转为有界停止，已读进度写入取消记录。

四项回归先在旧实现失败，验证异常后继续、KeyboardInterrupt回写、同期编辑与删除。另补重新绑定优先级和坏账户隔离。强制杀死进程或GitHub不可写时仍可能无法完成最终提交，已经落盘的进度与Cookie可用于恢复，失败明确返回状态写入错误。

## 保活恢复与告警

网络故障和没有返回新凭据的响应保持可重试。连续两次明确的登录失效才标记重绑，并按配置通知一次。成功续期或成功阅读清零失败计数。旧版本由warm网络失败留下的renewal提示可重新验证并恢复。单账户写入失败仍继续其他账户，返回状态写入错误；部分成功不会让整批失败。

四项回归在旧实现失败，新增账户保存失败隔离与旧状态恢复。通知使用替身验证阈值、一次性标记和文案，没有向真实邮箱或群发送。

## 无需cURL的自动取参

已在本机用用户微信扫码确认，程序自动打开正文并捕获获得succ/synckey确认的阅读请求，取齐appId/ps/pc/b/c/ci/co/sm/pr九个字段。随后通过Reader真实调用一次读取，read_count=1、level=L0、reason=ok，进程退出0。整个过程没有手工导入cURL。

正文入口改为实际/web/reader链接，直接导航避免命中作者链接，主动点下一页进入正文，监听整个浏览器上下文的请求及对应成功响应，保留Origin和Referer。新增capture指令可使用已有登录态自动重新获取参数。

已有登录态的重试也在本机实测通过，取参响应得到真实微信读书确认，同时走worker密文指令和加密回执并保留目标设置。该重试的GitHub存储使用内存后端，不能作为生产GitHub写入验收。GitHub Actions真实运行和完整20分钟计时尚未验证。

## 阅读通知

阅读L2恢复和L3失败按配置发送通知，L0/L1不发送，取消操作也不触发异常提醒。恢复消息、重绑消息、参数自动重试和状态写入失败使用对应文案，发送失败隔离渠道并保留阅读结果。

三项回归在修复前失败，相关37项测试通过。发送验证使用替身，未向真实邮箱或群发信。
