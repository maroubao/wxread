## 3. 关键决策

1. **renewal 只认本次响应新下发的 `wr_skey`**：读 `response.set_cookies["wr_skey"]`，退而取 `payload["wr_skey"]`；两者都没有 → `RenewalFailed`。若沿用 cookie 里的旧值，过期会话会"假装续期成功"，然后在下一轮重新跌进 -2012 死循环。
2. **`needs_login` 只由 L3 且原因 ∈ {`renew_failed`,`no_synckey`,`payload_invalid`} 触发**：网络类失败不能把账户判死，否则一次 GitHub 抖动就要用户重新扫码。
3. **`b`/`c` 不落状态**：`read_payload` 只持久化 `appId/ps/pc/ci/co/sm/pr`，`b`/`c` 每轮重新随机（对齐 `ARCHITECTURE.md` §4 不变量）。
4. **收尾语义**：`read_count==0` → 退出码 3（整轮无进展）；L3 但有读数 → 2（部分成功）。全账户失败 → worker 返回 1。
5. **`cmd_read(..., sleep=None)` 可选注入**：测试里传 `lambda _s: None` 跳过真实退避，否则一条用例要等 65 秒。
