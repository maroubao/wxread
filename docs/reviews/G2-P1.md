## 4. 偏离与决策（需知会）

1. **加密原语降级**（`THREAT-MODEL.md` §5.1 已同步改写）：XChaCha20-Poly1305-IETF → `crypto_secretbox` + 明文首行上下文前缀。原因：浏览器只能 vendor `tweetnacl`（无 XChaCha），两端须共用原语。绑定强度等价（前缀被 MAC 覆盖），由两条测试锁定。
2. **`crypto_box_seal` → 显式 nonce 的 `crypto_box`**：tweetnacl 无 blake2b 派生 nonce 的 seal 实现。封套字段定为 `{v, epk, n, c}`。
3. **`unseal` 长度校验**：原实现要求 ciphertext ≥ 48 字节，短回执被误判为损坏；改为 `MAC_LEN=16` 起判。
4. **`wr_skey` 存完整值**：旧 `main.py:96-106` 只保留前 8 位，v4 保留完整值（否则 renewal 后仍会失效）。

## 5. 残留风险

- `GitHubContents` 只做了单元级替身测试，真实 API 的错误体（422/409 语义差异）要到 G3 真跑才验证。
- `runs` 只按 `yyyy-mm` 分片裁剪到 200 条，跨月不做总量控制（有意为之：月度分片天然有界）。
