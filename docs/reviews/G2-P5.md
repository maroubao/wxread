## 3. 关键实现

- **canonical JSON 必须与 Python 一致**：`json.dumps(..., sort_keys=True, separators=(",",":"), ensure_ascii=False)` ↔ `canonicalJson()`；`tests/js/crypto.test.mjs` 用固定向量锁定，跨语言解密双向通过。
- **上下文前缀是安全边界**：`decryptState` 先比对 `wxread-state|<owner>/<repo>|v<kv>`，跨仓库搬运直接抛"上下文不符"（有测试）。
- **回执密钥一次性**：每次下发指令生成 `reply_key` 临时密钥对，私钥只存 `state.sessions`（内存 Map），刷新页面即失效——刷新后回执就看不到了，这是有意的。
- **二维码定位**：文件名带指纹不按时间排序，改用 `GET /commits?path=responses&per_page=1` 读最近一次提交信息里的 `qr <fp>`（`gh.js:latestCommitForPath`）。
- **凭据只在本机**：token 与状态密钥存 `localStorage`，"清除本机凭据"按钮一次抹掉四项；页面不含任何写入远端明文的路径。

## 4. 偏离

1. **没有真的跑 Lighthouse**：本机无 Chrome DevTools 环境，CI 也没装 lighthouse。已在 RUNBOOK G3 清单第 11 条留了人工验收（800px 无横滚 + Tab 可达）。补跑方式：`npx lighthouse <pages-url>/web/ --only-categories=accessibility`。
2. **编辑用 `prompt()`**：原生弹窗而不是自绘表单。理由：零构建前提下自绘表单要额外 80 行且容易破坏焦点管理；原生 prompt 键盘可达、屏幕阅读器可读。代价是样式不统一（记录在案）。
3. **导入 curl 没做页面表单**：curl 是一整段文本，粘进 textarea 再加密下发即可，但 P5 时间盒里先留了 API 层（`handle_import` 已支持），页面入口待补。

## 5. 残留风险

- `localStorage` 里的 token 是长期凭据，公网机器上使用有风险；建议用 fine-grained token 且只授本仓库。
- 页面每次刷新都要重新输状态密钥（除非勾选记住）；密钥存在 `localStorage` 意味着同源 XSS 可读。Pages 上只有本仓库的静态文件，攻击面等于仓库本身。
- tweetnacl 是 2019 年的实现，未做恒定时间加固（JS 本身做不到）；威胁模型里已接受（攻击者需要本地执行能力）。
