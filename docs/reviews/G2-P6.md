## 3. 密钥扫描的规则

- 命中即失败：明文 `wr_skey`/`wr_vid` 赋值、`ghp_`/`github_pat_`、私钥块、Slack token。
- 白名单：`tests/`（夹具是假数据）、`docs/`（文档里的示例值）、`*.md`。
- 黑名单文件：`.qr-cookies.json`、`qr-latest.png`、`qr-scan.png` 出现即失败。
- 口径统一：只在 **git 可见文件**上扫描（`git ls-files --cached --others --exclude-standard`），所以本机残留的 `.qr-cookies.json` 不会造成假失败，而一旦 `git add -f` 上去就必失败。

## 4. 偏离

1. **Secret 清理只能人工**：`WXREAD_CURL_BASH`、`PUSH_METHOD`、`WXPUSHER_SPT`、`SERVERCHAN_SPT`、`READ_NUM` 这类仓库 Secret/Variable 我改不了，只能列清单让人删（RUNBOOK §1 已列必要 Secret，其余即待删）。
2. **`tests.yml` 的 node job 也装了 Python**：跨语言测试需要真 Python 生成 fixture，这不是"多余依赖"，而是该测试的意义所在（证明两边字节一致）。

## 5. 残留风险

- CI 里没有 Playwright 相关 job：`qr.py` 的真机路径只能靠 G3 手工验收；单测用 FakePage 覆盖轮询逻辑。
- `scan_secrets.py` 是启发式，无法发现"被 base64 后再拼进字符串"的凭据；真正的兜底是"凭据从不以明文离开浏览器"这条设计。
- 未提交：本轮所有改动仍在工作区（`git status` 一堆未跟踪/已删除），提交与否由使用者决定。
